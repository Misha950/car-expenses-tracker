Підхід до тестування

Мета

Переконатися, що ключова логіка застосунку працює правильно і що зміни в коді не ламають уже готові функції.

Рівні тестування

1. Автоматичні модульні тести (xUnit)
   Перевіряють окремі шматки логіки без запуску інтерфейсу:
   - обчислення суми заправки (TotalCost = Liters * PricePerLiter)
   - валідація даних: літри, ціна та сума повинні бути додатними
   - розрахунки статистики (підсумок за період, витрата пального)

2. Ручне тестування інтерфейсу
   Для кожної історії користувача з docs/user-stories.md перевіряємо критерії прийняття: додавання, редагування, видалення запису, відображення у списку.

3. Автоматична перевірка в GitHub Actions
   На кожен Pull Request проєкт збирається, а тести запускаються командою dotnet test.

Інструменти

| Що | Інструмент |
|---|---|
| Модульні тести | xUnit |
| Запуск локально | dotnet test |
| Автоматизація | GitHub Actions |

Приклад тесту

Заправка 40 літрів по 50 грн за літр має мати TotalCost = 2000.

Назва тестового проєкту

CarExpensesTracker.Tests. Саме така назва потрібна, щоб GitHub Actions знаходив тести автоматично.

Поточний стан

   Тестовий проєкт CarExpensesTracker.Tests створено (xUnit). Зараз у ньому є тести розрахунку суми заправки (TotalCost). Далі додаються тести валідації та сервісу звітів ReportService. Автоматична збірка і запуск тестів працюють у GitHub Actions.
