Функціональні вимоги

Заправки

1. Система повинна дозволяти додати новий запис заправки з полями: 
   дата, кількість пального (літри), ціна за літр, загальна сума, 
   поточний пробіг
2. Система повинна дозволяти редагувати існуючий запис заправки
3. Система повинна дозволяти видаляти запис заправки
4. Система повинна відображати список усіх заправок у вигляді таблиці, 
   відсортованої за датою (найновіші зверху)
5. Система повинна перевіряти, що кількість літрів і сума є додатними 
   числами перед збереженням запису

Ремонти та ТО

6. Система повинна дозволяти додати новий запис ремонту/ТО з полями: 
   дата, тип (ремонт/ТО), опис виконаних робіт, вартість, пробіг, 
   дата наступного ТО (необов'язкове поле)
7. Система повинна дозволяти редагувати існуючий запис ремонту/ТО
8. Система повинна дозволяти видаляти запис ремонту/ТО
9. Система повинна відображати список усіх ремонтів/ТО у вигляді таблиці

Інші витрати

10. Система повинна дозволяти додати запис іншої витрати з полями: 
    дата, тип (штраф/страховка/паркування/інше), сума, коментар
11. Система повинна дозволяти редагувати та видаляти запис іншої витрати

Звіти та статистика

12. Система повинна відображати підсумкову суму витрат за обраний 
    користувачем період (день/тиждень/місяць/рік)
13. Система повинна відображати графік витрат з розбивкою по категоріях 
    (заправки/ремонти/інші витрати)
14. Система повинна дозволяти фільтрувати відображувані дані за 
    вказаним періодом часу

Загальні вимоги

15. Усі дані повинні зберігатися локально в базі даних SQLite
16. Система повинна зберігати внесені зміни одразу після підтвердження 
    користувачем (без окремої кнопки "Зберегти все")

Нефункціональні вимоги

1. Продуктивність: застосунок повинен запускатися не довше 3 секунд 
   після запуску
2. Продуктивність: додавання нового запису (заправка/ремонт/витрата) 
   повинно відображатися у списку миттєво, без помітної затримки
3. Надійність: дані не повинні втрачатися при аварійному закритті 
   застосунку — кожен запис зберігається в базу одразу після 
   підтвердження, а не при закритті програми
4. Безпека: усі дані зберігаються локально на пристрої користувача, 
   без передачі через мережу чи хмару
5. Зручність використання: інтерфейс повинен бути зрозумілим без 
   додаткової інструкції — усі основні дії (додати/редагувати/видалити) 
   доступні не більш ніж у 2 кліки з головного екрана
6. Сумісність: застосунок повинен коректно працювати на Windows, 
   macOS та Linux (завдяки Avalonia UI)
7. Логування: усі значущі дії користувача (додавання, редагування, 
   видалення записів) повинні фіксуватися в лог-файл для діагностики 
   можливих проблем
8. Валідація: усі форми вводу повинні перевіряти коректність даних 
   перед збереженням і показувати зрозуміле повідомлення про помилку
