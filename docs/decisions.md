# Ключові технічні рішення

## Avalonia UI

Обрали Avalonia, бо застосунок має працювати на Windows, macOS і Linux, а команда використовує різні системи. Avalonia дозволяє писати інтерфейс у XAML на C# і мати один код для всіх платформ. Альтернатива WPF працює лише на Windows.

## MVVM і CommunityToolkit.Mvvm

Логіку екранів відокремлено від розмітки: кожен екран має View (XAML) і ViewModel (C#). Це спрощує тестування логіки без запуску інтерфейсу. CommunityToolkit.Mvvm генерує повторюваний код (властивості та команди) атрибутами, тому ViewModel коротші.

## SQLite

Дані зберігаються локально у файлі, без хмари й сервера. Для обліку витрат одного користувача цього достатньо, а встановлювати нічого не треба: база створюється автоматично при першому запуску. Дані лишаються приватними на комп'ютері користувача.

## Entity Framework Core

EF Core дозволяє працювати з базою через C#-класи (Models) замість ручних SQL-запитів. Це зменшує кількість помилок і дає змогу легко змінювати модель даних. Для SQLite використовується пакет Microsoft.EntityFrameworkCore.Sqlite.

## LiveCharts2 (превʼю-версія 2.1)

Для графіків обрали LiveCharts2, бо він підтримує Avalonia. Стабільна версія 2.0.x виявилась несумісною з Avalonia 12 (екран із графіками не відображався), тому використано превʼю 2.1.0-dev-798, де підтримку додано. Ризик: превʼю-версія може мати помилки, тому графіки перевіряються вручну.

## Журналювання у текстовий файл

Дії користувача (додавання, зміна, видалення записів) записуються у текстовий файл `log.txt` поруч із базою даних. Це простий спосіб бачити історію дій без додаткових бібліотек.

## Робота через гілки і Pull Request

Прямі коміти в main заборонені. Кожна задача робиться в окремій гілці, змінюється через Pull Request і мерджиться після Approve іншого учасника. GitHub Actions збирає проєкт і запускає тести на кожен PR.
